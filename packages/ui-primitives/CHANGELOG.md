# @clarusjs/ui-primitives

## 0.1.0

### Minor Changes

- [#474](https://github.com/forinda/clarusjs/pull/474) [`57a0b91`](https://github.com/forinda/clarusjs/commit/57a0b91c53294ec5986a6b5e141a731397025769) Thanks [@forinda](https://github.com/forinda)! - Headless parts, native-first ([#465](https://github.com/forinda/clarusjs/issues/465)): `dialog.tscl` with `dialog-trigger.tscl` and `dialog-close.tscl` (a native `<dialog>` opened with the browser's command invokers: focus kept in it, the page inert, Escape and a click outside close it), `popover.tscl` with `popover-trigger.tscl` (the `popover` attribute, placed with CSS anchor positioning by `side` and `align`), `accordion-item.tscl` (`<details>`, exclusive by `group`), none of them shipping JavaScript; and `switch.tscl`, `checkbox.tscl` and `field.tscl` (small islands: native inputs, `[(checked)]` / `[(value)]`, a field's label, description and error wired by id, its error shown once left, Base UI's `data-` state). No styles: `data-part` names each element.

- [#489](https://github.com/forinda/clarusjs/pull/489) [`ebf0596`](https://github.com/forinda/clarusjs/commit/ebf0596c69ba02e05e2ecc1139147a6b5e4ada5a) Thanks [@forinda](https://github.com/forinda)! - Menu ([#465](https://github.com/forinda/clarusjs/issues/465)): `menu.tscl` (a small island) with `menu-trigger.tscl`, `menu-list.tscl` and `menu-item.tscl` (no script). The list is a popover opened by its trigger, so opening, closing, Escape and a click outside come from the browser; the menu moves focus in on open, keeps `aria-expanded` in step, adds arrow keys, Home, End and typeahead, and sends `(select)` with the item's value (cancellable). `@clarusjs/ui` styles them.

- [#487](https://github.com/forinda/clarusjs/pull/487) [`ec4cb9e`](https://github.com/forinda/clarusjs/commit/ec4cb9e8e9d534ee0ebfc04bc21d39d0a17b30e7) Thanks [@forinda](https://github.com/forinda)! - Radio group ([#465](https://github.com/forinda/clarusjs/issues/465)): `radio-group.tscl` (a small island) with `radio.tscl` (no script: it reads the group's name and value from context, so the server writes which one is checked). Native radios in a fieldset: arrow keys, one Tab stop and form submission from the browser. `[(value)]` binds the value and `(change)` can be cancelled. `@clarusjs/ui` styles them.

- [#474](https://github.com/forinda/clarusjs/pull/474) [`5a8fe18`](https://github.com/forinda/clarusjs/commit/5a8fe1846f9663d0c1fbb9494e458de1a113e1d3) Thanks [@forinda](https://github.com/forinda)! - Select and Combobox ([#466](https://github.com/forinda/clarusjs/issues/466)): `select.tscl`, a native `<select>` that's the customizable select (`appearance: base-select`) where the browser has it, with `[(value)]` and `(change)`; and `combobox.tscl`, the docs site's combobox moved into the package and made headless (`data-part` on each element, `data-highlighted` on the active option, only its list's positioning styled): one pick or several, options from the server, keyboard, and a `(change)` a parent can cancel.

- [#481](https://github.com/forinda/clarusjs/pull/481) [`aac32f7`](https://github.com/forinda/clarusjs/commit/aac32f77c8518cb553dba517b05c9ca21a2737e0) Thanks [@forinda](https://github.com/forinda)! - Tabs ([#465](https://github.com/forinda/clarusjs/issues/465)), Radix-shaped: `tabs.tscl` (a small island) with `tab-list.tscl`, `tab.tscl` and `tab-panel.tscl`, which read the selection from context and ship nothing, so the server writes every ARIA attribute and `hidden`. Arrow keys, Home and End select; `[(value)]` binds the selected value and `(change)` can be cancelled. `@clarusjs/ui` styles them.

- [#488](https://github.com/forinda/clarusjs/pull/488) [`5ddef98`](https://github.com/forinda/clarusjs/commit/5ddef98f24fb0b3d7c992300d746edfe6a665a15) Thanks [@forinda](https://github.com/forinda)! - Tooltip ([#465](https://github.com/forinda/clarusjs/issues/465)): `tooltip.tscl` (a hint popover, `popover="hint"`, anchored to its trigger) and `tooltip-trigger.tscl` (a button described by it). Browsers with interest invokers (`interestfor`) show and hide it themselves; elsewhere the trigger, a small island, does: on hover after a short delay, on focus, kept open while the pointer is on it, closed on Escape, blur or leaving. `@clarusjs/ui` styles it.

- [#474](https://github.com/forinda/clarusjs/pull/474) [`a8ea351`](https://github.com/forinda/clarusjs/commit/a8ea3512a4807e3398b01b4747fc027d29222976) Thanks [@forinda](https://github.com/forinda)! - `@clarusjs/ui-primitives` ([#464](https://github.com/forinda/clarusjs/issues/464)), a new package: accessible behaviours as small DOM functions, each `(element, options) → stop`: `rovingFocus` (one Tab stop, arrow keys by orientation and RTL, Home/End, disabled items skipped), `typeahead` (a repeated key cycles), `dismiss` (Escape and outside press, stacked layers, a cancelable `cl:dismiss` event), `enter` / `exit` (Base UI's `data-open`, `data-starting-style`, `data-ending-style` for CSS transitions), `focusReturn` and `position` (`data-side` and the `--anchor-width`, `--available-height`, `--transform-origin` variables). Each is its own module, no dependencies, about 2.3 KB gzip for all six.

  clarusjs: `[use]="fn"` on an element in an island calls `fn(element)` in the browser when the island attaches, and the function it returns when the element's branch, row or island goes (a list runs several). The server renders a `data-cl-u` marker only; `clarusjs check` types the element by its tag.

### Patch Changes

- [#485](https://github.com/forinda/clarusjs/pull/485) [`6d54f6f`](https://github.com/forinda/clarusjs/commit/6d54f6f1e610b5449a7caeb68ed50767dede92a7) Thanks [@forinda](https://github.com/forinda)! - Review fixes for context and island content ([#465](https://github.com/forinda/clarusjs/issues/465)): `provide` may only be called (a bare reference is a located error in the build and in `check`), an import may rename it (`import { provide as register }`) and any import binding the name `provide` is rejected, comments or not, `@context` names like `Object` work, a provided `__proto__` key reaches re-rendered content, an island's markers never include those of an island in its slot content, a `@model` field in a component inside another island's slot takes the right path, and an island whose content reads a nested provider that failed to load is retried with it instead of failing for good. Menu items name their menu (`data-menu`), so arrow keys and typeahead skip a nested menu's items; a radio group follows its value after a reset of the form it is in now (also after a fragment swap moved it); a focused tooltip trigger keeps its tooltip open when the pointer leaves.

- [#485](https://github.com/forinda/clarusjs/pull/485) [`b02ebc8`](https://github.com/forinda/clarusjs/commit/b02ebc83e348a81cd71e1e437902ec43bb71ad66) Thanks [@forinda](https://github.com/forinda)! - Context fixes ([#465](https://github.com/forinda/clarusjs/issues/465)): `@context` reads only what was provided (a name like `toString` no longer reads the object's own); a `provide` key must be a name `@context` can read; `clarusjs check` reports a script's own `provide` as the build does. The Tabs docs no longer suggest `[(value)]` and `(change)`, which need a parent island that can pass content to the tabs.

- [#486](https://github.com/forinda/clarusjs/pull/486) [`e61e09c`](https://github.com/forinda/clarusjs/commit/e61e09c6e2cece2d8a051f095afd075e1788e042) Thanks [@forinda](https://github.com/forinda)! - Islands pass content to islands ([#465](https://github.com/forinda/clarusjs/issues/465)): content written inside an island can go to another island's `<slot />`, with its holes, handlers, blocks and `[use]`; each island wires only its own. An island's slot content now sits between `<!--[s-->` and `<!--]s-->` (a new marker in the HTML contract), and the runtime decides which island owns a node across those ranges. The "can't take content from inside another island yet" error is gone. Forms paths of fields in slot content come from the island that wrote them. Tabs' `[(value)]` and `(change)` work inside islands.
